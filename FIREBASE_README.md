# Project Setup: Firebase Configuration

This project utilizes Firebase for its backend services. To run this project successfully, you'll need to set up Firebase and ensure the necessary configuration files and keys are in place.

**Important Note:** The configuration files mentioned below (google-services.json, GoogleService-Info.plist, firebase_options.dart, the Firebase Admin SDK JSON, and your VAPID key) are **NOT** included in this repository. They contain sensitive API keys and project-specific identifiers that should never be committed to version control. You will need to generate or download them yourself.

## 1. Firebase Project Setup (Initial Setup if not already done)

If you haven't already, you'll need a Firebase project.

1. **Create a Firebase Project:**
   - Go to the <a href="https://console.firebase.google.com/" target="_blank" rel="noopener noreferrer">Firebase Console</a>.
   - Click "Add project" and follow the on-screen instructions to create a new project.
2. **Install Firebase CLI:**
   - Ensure you have Node.js and npm installed. If not, download from <a href="https://nodejs.org/" target="_blank" rel="noopener noreferrer">nodejs.org</a>.
   - Open your terminal/command prompt and run:
   ```bash
   npm install -g firebase-tools
   ```
3. **Log in to Firebase CLI:**
   - In your terminal, run:
   ```bash
   firebase login
   ```
   - This will open a browser for authentication.
4. **Install FlutterFire CLI:**
   - From any directory, run:
   ```bash
   dart pub global activate flutterfire_cli
   ```

## 2. Generating Client-Side Configuration Files (for Flutter App)

These files allow your Flutter application to connect to your Firebase project.

This project has already had `flutterfire configure` ran, which is the primary way these files are generated. If for any reason they are missing or you need to re-generate them (e.g., adding a new platform or linking to a different Firebase project), here's how:

### firebase_options.dart

- **Purpose:** This Dart file contains the Firebase configuration (API keys, App IDs, Project ID) for each platform (Android, iOS, Web, etc.) your Flutter app supports. The FlutterFire SDK uses this to initialize Firebase.
- **Location:** This file is automatically generated in your Flutter project's `lib/` directory (e.g., `lib/firebase_options.dart`).
- **Generation (Command Line):**
  1.  Navigate to your Flutter project's root directory in your terminal:
  ```bash
  cd path/to/your_flutter_project
  ```
  2.  Run the FlutterFire configuration command:
  ```bash
  flutterfire configure
  ```
  3.  Follow the prompts to select your Firebase project and the platforms you want to configure. This command will create or update `lib/firebase_options.dart`.

### google-services.json (for Android)

- **Purpose:** This JSON file contains configuration information specific to your Android Firebase app, including your project ID, API key, and other Firebase service configurations.
- **Location:** This file must be placed in the `android/app/` directory of your Flutter project.
- **Generation/Download:**
  - **Option A (Recommended for existing `flutterfire configure` projects):** The flutterfire configure command (mentioned above) should automatically download and place this file in the correct location for Android when you select Android as a target platform.
  - **Option B (Manual Download):** If you need to manually download it:
    1. Go to the <a href="https://console.firebase.google.com/" target="_blank" rel="noopener noreferrer">Firebase Console</a>.
    2. Select your project.
    3. In "Project settings" (gear icon), find the "Your apps" section.
    4. Click on your Android app's package name (e.g., com.example.your_app_id).
    5. Click the "Download `google-services.json`" button.
    6. Place the downloaded `google-services.json` file into your Flutter project's `android/app/` directory.

### GoogleService-Info.plist (for iOS)

- **Purpose:** This Property List (plist) file contains configuration information specific to your iOS Firebase app, similar to google-services.json for Android.
- **Location:** This file must be placed in the `ios/Runner/` directory of your Flutter project and also **added to your Xcode project.**
- **Generation/Download:**
  - **Option A (Recommended for existing `flutterfire configure` projects):** The `flutterfire configure` command (mentioned above) should automatically download and place this file in the correct location for iOS when you select iOS as a target platform. It _might_ also handle adding it to the Xcode project, but it's good to verify.
  - **Option B (Manual Download & Xcode Integration):** If you need to manually download it or verify its Xcode integration:
    1. Go to the <a href="https://console.firebase.google.com/" target="_blank" rel="noopener noreferrer">Firebase Console</a>.
    2. Select your project.
    3. In "Project settings" (gear icon), find the "Your apps" section.
    4. Click on your iOS app's bundle ID (e.g., com.example.yourAppId).
    5. Click the "Download `GoogleService-Info.plist`" button.
    6. **Crucially, add this file to your Xcode project:**
       - Open your Flutter project's iOS workspace in Xcode:
       ```bash
       open ios/Runner.xcworkspace
       ```
       - In Xcode, drag the downloaded `GoogleService-Info.plist` file from your Finder/File Explorer into the Runner folder in Xcode's Project Navigator (left sidebar).
       - When prompted, ensure "Copy items if needed" is checked and "Add to targets" has your main app target selected.

## 3. Firebase Admin SDK JSON (for your Backend/Flask)

- Purpose: This JSON file contains a private key for a Firebase service account. It's used by server-side applications (like your Flask backend) to authenticate with Firebase services with administrative privileges (e.g., sending FCM messages, accessing databases securely).
- Location: This file should be stored securely on your server, _outside_ of your publicly accessible web directories. In your Flask project, you would typically reference its path in your environment variables or directly in your application's configuration.
- **Generation (Firebase Console):**
  1.  Go to the <a href="https://console.firebase.google.com/" target="_blank" rel="noopener noreferrer">Firebase Console</a>.
  2.  Select your project.
  3.  Go to **Project settings** (gear icon).
  4.  Select the **Service accounts** tab.
  5.  Under "Firebase Admin SDK," click "Generate new private key."
  6.  Confirm by clicking "Generate key."
  7.  A JSON file (e.g., `your-project-name-firebase-adminsdk-xxxxx-xxxxxx.json`) will be downloaded.
- **Usage in Flask:**

  - **DO NOT** commit this file to your repository.
  - Place this file in a secure location on your server where your Flask application can access it.
  - In your Flask application, you'll initialize the Firebase Admin SDK by providing the path to this JSON file. For example:

  ```python
  import firebase_admin
  from firebase_admin import credentials, messaging
  import os

  # Recommended: Get the path to the service account key from an environment variable
  # For example, in your .env file: FIREBASE_ADMIN_SDK_PATH="/path/to/your-project-name-firebase-adminsdk-xxxxx-xxxxxx.json"

  service_account_path = os.getenv("FIREBASE_ADMIN_SDK_PATH")

  if service_account_path and os.path.exists(service_account_path):
      cred = credentials.Certificate(service_account_path)
      firebase_admin.initialize_app(cred)
      print("Firebase Admin SDK initialized successfully.")
  else:
      print("Error: Firebase Admin SDK JSON file path not found or invalid.") # Handle this error appropriately, e.g., exit or raise an exception
  ```

## 4. VAPID Key (for Web Push Notifications)

- **Purpose:** VAPID (Voluntary Application Server Identification) keys are a pair of public and private keys that allow your application server to identify itself to the push service when sending web push notifications. The public key is registered with FCM, and the private key is used by your server (e.g., Flask) to sign push requests.
- **Location:** The public key needs to be registered in your Firebase project settings. The private key must be securely stored and used by your backend.
- **Generation (Command Line):**
  - You can generate a VAPID key pair using the Firebase CLI:
  ```bash
  firebase messaging:web push-config
  ```
- This command will output a public and private key. It will also offer to register the public key with your Firebase project. If it asks, confirm to save it.
- **Alternatively, you can generate them programmatically (e.g., in Python) or using online tools if you prefer, but the Firebase CLI is the most straightforward.**
- Configuration in Firebase Console:
  1.  Go to the <a href="https://console.firebase.google.com/" target="_blank" rel="noopener noreferrer">Firebase Console</a>.
  2.  Select your project.
  3.  Go to **Project settings** (gear icon).
  4.  Select the **Cloud Messaging** tab.
  5.  Scroll down to the "Web configuration" section.
  6.  If you generated the key via the CLI and agreed to save it, it might already be here. If not, click "Generate key pair" or paste your public key if you generated it elsewhere.
- **Usage in your Backend (Flask):**

  - The private VAPID key is used when sending push notifications to web clients via the Firebase Admin SDK. You'll typically configure your Admin SDK to use it for web push.
  - **DO NOT** commit your private VAPID key to your repository. Store it securely, ideally as an environment variable or in a secure configuration management system.

  ```python
  # Example (using firebase_admin in Flask to send web push with VAPID)
  # Ensure your VAPID private key is loaded securely, e.g., from an environment variable
  # os.getenv("VAPID_PRIVATE_KEY")

  # When sending a message (simplified example, actual implementation might vary slightly based on your needs)

  message = messaging.Message(
      notification=messaging.Notification(
          title="Hello from Flask!",
          body="This is a web push notification.",
      ),
      token="device_registration_token_for_web",
      webpush=messaging.WebpushConfig(
          headers={
              "Urgency": "high"
          },
          # You might need to configure the APNS or WebPush options directly
          # For VAPID authentication, it's typically configured at the app level
          # during initialization if not done via the Console.
          # The Firebase Admin SDK generally handles the VAPID signing if the public key
          # is registered in the console and the Admin SDK is initialized correctly.
          # For explicit VAPID usage in code, it's more common when not using FCM's Admin SDK
          # and directly interacting with Web Push APIs.
          # With Firebase Admin SDK, once the public key is registered in the console,
          # and your server is authenticated with the Admin SDK, it usually handles
          # the VAPID signing for you when sending to web tokens.
      )
  )
  # The VAPID private key is used internally by the Admin SDK if it's set up correctly.
  # You don't usually pass the private key directly in the message payload.
  # The Admin SDK's initialization often links to your project's web config where VAPID is set.
  ```

  - **Key takeaway:** Once the VAPID public key is set in your Firebase project's Cloud Messaging settings, and your Flask backend is initialized with the Firebase Admin SDK using the service account JSON, the Admin SDK typically handles the necessary VAPID authentication when sending messages to web tokens associated with that project.
